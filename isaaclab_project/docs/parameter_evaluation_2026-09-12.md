| 실행 방식 | 업데이트당 새 transition | minibatch 크기 | 전체 새 transition |
| --- | ---: | ---: | ---: |

각 업데이트는 같은 rollout을 5 epoch 재사용한다. 위 transition 수에 epoch 수를 곱해서 새 경험 수로 세면 안 된다. 기본 PowerShell 실행은 Python 설정 기본보다 전체 경험 수가 **12배 적다**. 4환경은 실행 확인에는 가볍지만, 24관절 정책의 본 학습용으로 충분한지는 별도 비교가 필요하다.

### 충돌 크기와 실물 치수는 구분해야 한다

현재 URDF의 관절 변환과 모든 박스 충돌체 꼭짓점을 계산한 초기 자세의 외곽 치수는 다음과 같다. 시뮬레이션으로 내려앉은 자세가 아니라 **지정 초기 자세의 기하 계산**이다.

| 모델 | 충돌체 전체 X 폭 | Y 폭 | 지정 초기 root 높이에서 최고점 |
| --- | ---: | ---: | ---: |
| 기본 8족 | 0.68403 m | 0.68403 m | 바닥 위 0.22000 m |
| CAD 8족 | 0.45479 m | 0.45479 m | 0.14333 m |

통로 계산용 폭 0.69 / 0.46 m는 이 초기 자세보다 약간 커서 초기 배치에는 합리적이다. 그러나 다리를 움직일 때의 전체 운동 범위를 보장하는 값은 아니다. 실제 협소 통과 시험에서는 접촉 빈도와 통과율을 확인해야 한다.

기본 URDF는 링크 길이 86.17 / 100 / 120 mm를 사용한다. CAD 모델은 문서에 기록된 단위·관절 중심 추정과 다른 영점을 사용하며, 임시 몸체 질량 0.5 kg 및 박스 관성 근사가 포함된다. **CAD 외형이 있다는 이유만으로 현재 질량·축·관성이 실측값이라는 의미는 아니다.**

### 토크 상한과 탐색 크기가 맞물린다

정지 상태에서 D항과 외력을 무시하면 P항이 토크 상한에 도달하는 위치 오차는 다음과 같다.

```text
포화 시작 오차 ≈ 0.980665 / 8 = 0.12258 rad = 7.02°
baseline 최대 행동의 P항 = 8 × 0.30 = 2.40 N·m
CAD 최대 행동의 P항      = 8 × 0.20 = 1.60 N·m
```

행동은 목표 관절각의 오프셋이며, 위 수치는 실제 토크 측정값이 아니다. 다만 허용 행동 범위가 P항 포화 시작점보다 크다는 사실은 분명하다. 초기 정책 표준편차 0.35에 따른 목표각 표준편차는 기본 로봇 약 6.02°, CAD 약 4.01°다. 평균 0, 현재 관절각이 기본 자세, 속도 0인 정규 탐색을 가정하면 순수 P항의 포화 구간 진입 확률은 관절당 약 **24.3% / 8.0%**다. 실제 값은 정책 평균·관절 상태·접촉에 따라 달라진다.

**평가:** 200 Hz 물리 / 50 Hz 목표 갱신과 solver 설정은 우선 유지할 수 있다. 먼저 관절 추종 오차, 토크 포화 비율, 발 미끄럼을 측정하고, 탐색 표준편차나 행동 평활화를 비교하는 편이 낫다. 토크 제한, 속도 제한, PD 이득을 한꺼번에 바꾸지 않는다. 자기충돌 비활성은 초기 학습 비용을 줄이지만 협소 통로에서 다리끼리 관통하는 동작을 허용할 수 있다.

ImplicitActuator는 물리 엔진의 PD 제어를 사용한다. 보상 계산에 쓰는 `applied_torque`는 여기서 근사한 PD 토크를 클리핑한 값이며 실측 모터 전력이나 실제 전달 토크 기록이 아니다. [Isaac Lab 2.1 actuator 문서](https://isaac-sim.github.io/IsaacLab/v2.1.0/source/api/lab/isaaclab.actuators.html), [저장소의 구현][implicit_actuator].

## 4. 환경별 난이도 평가

근거: [지형 공식][layout], [동적 위험 구현][runtime]. 아래 `d`는 `environment_difficulty`다. 난이도는 실행 중 고정되며, 자동 커리큘럼은 없다. `mixed`는 좁은 통로 + 진동 + 낙하물이며, 낮은 천장과 요철은 포함하지 않는다.

비평지의 시작점은 X=-1.6 m, 목표 중심은 X=+1.6 m다. 목표 반경 0.3 m까지 최소 약 **2.9 m**를 이동해야 하므로, 20초 내 완주에 필요한 직선 평균 속도는 약 **0.145 m/s**다. 우회·대기 시간을 포함하면 이동 중에는 더 빨라야 한다. 같은 20초가 모든 로봇과 환경에 적절한지는 아직 확인되지 않았다.

### 좁은 틈과 낮은 천장

```text
통로 폭 = 로봇 설정 폭 × (1.38 − 0.30d)
천장 아래 높이 = 로봇 설정 높이 + 0.12 − 0.08d
```

| 항목 | d=0 | d=0.5, 기본 | d=1 |
| --- | ---: | ---: | ---: |
| 기본 로봇 통로 폭 | 95.22 cm | 84.87 cm | 74.52 cm |
| 기본 로봇 설정 폭 대비 한쪽 여유 | 13.11 cm | 7.94 cm | 2.76 cm |
| CAD 통로 폭 | 63.48 cm | 56.58 cm | 49.68 cm |
| CAD 설정 폭 대비 한쪽 여유 | 8.74 cm | 5.29 cm | 1.84 cm |
| 기본 로봇 천장 아래 높이 | 40.0 cm | 36.0 cm | 32.0 cm |
| CAD 천장 아래 높이 | 36.0 cm | 32.0 cm | 28.0 cm |

**평가:** 최대 난이도에서는 수평 방향으로 충분히 좁아진다. 반면 낮은 천장은 최고 난이도에서도 초기 충돌체 최고점보다 기본 로봇 약 **10.0 cm**, CAD 약 **13.7 cm** 높다. 따라서 현재 설정만으로는 몸을 낮춰야만 지나가는 훈련이라고 보기 어렵다. 낮은 자세가 목적이라면 실제 안정 자세의 최고점과 낮출 수 있는 관절 범위를 측정한 뒤 천장 기준을 별도로 정해야 한다.

### 진동 바닥

```text
수직 진폭 A = (0.004 + 0.014d) × U(0.8, 1.0) m
주파수 f    = (0.8 + 2.2d) × U(0.85, 1.15) Hz
수평 X 진폭 = A / 2, 수직과 동일한 위상
수직 속도 상한 = A × 2πf
수직 가속도 상한 = A × (2πf)²
```

| 항목 | d=0 | d=0.5 | d=1 |
| --- | ---: | ---: | ---: |
| 수직 진폭 범위 | 3.2–4.0 mm | 8.8–11.0 mm | 14.4–18.0 mm |
| 주파수 범위 | 0.68–0.92 Hz | 1.615–2.185 Hz | 2.55–3.45 Hz |
| 명령 파형의 최대 수직 속도 | 0.023 m/s | 0.151 m/s | 0.390 m/s |
| 명령 파형의 최대 수직 가속도 | 0.134 m/s² | 2.073 m/s² | 8.458 m/s² |
| 중력 9.81 m/s² 대비 | 0.014 g | 0.211 g | 0.862 g |

바닥은 100 kg, 중력 비활성, 기본 윗면 높이 0.08 m인 동적 강체다. 매 물리 스텝 속도로 목표 궤적을 추종하고, 속도 명령은 축당 ±1 m/s, 회전 보정은 축당 ±5 rad/s로 제한한다. 로봇과의 반작용으로 실제 파형은 명령 파형과 달라질 수 있다.

**평가:** 난이도가 진폭과 주파수를 함께 높이므로 가속도는 선형으로 증가하지 않는다. 특히 0.5에서 1로 올리면 최대 가속도가 약 4.1배가 된다. 표의 값은 랜덤화 상한을 포함한다. 최고 난이도는 발에 걸리는 정상력이 작아지는 구간과 수평 가속도가 겹쳐 부담이 크다. 쉬운 실험에서는 진폭·주파수를 분리해 올리고, 실제 바닥 추종 오차·접촉 유지율·미끄럼을 함께 측정하는 편이 원인을 파악하기 쉽다.

낙하 계산은 `h = 생성 중심 높이 − 반지름`, `g=9.81`, 초기 속도 0, 항력·중간 충돌이 없는 정지 평지를 가정했다. **실제 로봇에 전달되는 충격 에너지가 아니다.** 로봇과는 지면보다 높은 곳에서 먼저 충돌할 수 있고, 움직이는 바닥·접촉·감쇠가 결과를 바꾼다.

풀 크기는 환경당 4개로 제한된다. 최초 투하는 슬롯별 `0.8 + slot × (1.7−d) + U(0,0.5)`초에 예약하며, 이후 각 슬롯이 독립적으로 재사용된다. 따라서 투하 간격이 항상 표의 평균값처럼 일정하지는 않다. 투하 중심은 X ∈ [-0.85, 0.85] m, Y ∈ 통로 폭의 ±0.325 범위다. 시작·목표 위치에 직접 생성하지 않는 구성은 적절하지만, 튀거나 구르는 물체까지 그 영역에 머물도록 제한한 것은 아니다.

**평가:** 가장 쉬운 단계도 반지름 4.5 cm, 150 g의 물체가 떨어지는 환경이다. 난이도 1의 물체 하나는 CAD 6족 질량의 약 21.6%다. 질량·크기·높이·빈도가 동시에 올라가므로 실패 원인을 분리하기 어렵다. 초기 비교에서는 이 항목들을 분리하고, 피격률과 완주율을 함께 본다. 200 Hz에서 최대 낙하 속도의 1스텝 이동량은 약 3.2 cm이므로 작은 링크와의 충돌 누락도 스모크 검사에서 확인할 항목이다. 현재 PhysX 기본 `enable_ccd=False`를 그대로 사용한다.

### 요철

최고 단차는 `로봇 설정 높이 × (0.06 + 0.17d)`이며, 세 단차의 높이 비율은 0.65 / 1.0 / 0.8이다. 각 단차의 X방향 길이는 28 cm, 위치는 -0.8 / 0 / +0.8 m다.

| 최고 단차 | d=0 | d=0.5 | d=1 |
| --- | ---: | ---: | ---: |
| 기본 로봇 | 1.68 cm | 4.06 cm | 6.44 cm |
| CAD | 1.44 cm | 3.48 cm | 5.52 cm |

**평가:** 통로 전체를 가로질러 돌아서 피하기 어렵고 단계적 실험에 적합하다. 다만 설정 높이로 단차를 정했기 때문에 실제 발끝 도달 범위·허용 보행 자세에 비례한다고 보장할 수 없다. CAD의 짧은 관절 간격과 ±0.20 rad 행동 범위에서 최고 단차를 넘을 수 있는지 먼저 확인해야 한다.

## 5. 관측 정보

근거: [관측 구성][runtime], [수평 거리·높이 계산][sensing], [정책 입력 구성][env].

| 모델 | 평지 관측 | 비평지 관측 | 행동 |
| --- | ---: | ---: | ---: |
| 기본 8족 / CAD 8족 | 84 | 116 | 24 |
| CAD 6족 | 66 | 98 | 18 |

추가 32차원은 수평 거리 16개, 3×3 지지면 높이 9개, 바닥 속도 3개, 최근접 낙하물 상대 위치 3개와 월드 수직 속도 1개다. 수평 거리 범위는 2 m, 광선 간격은 22.5°이고, 높이 샘플은 몸체 중심에서 X/Y 각각 -0.3 / 0 / +0.3 m 지점이다.

**현재 확인되는 제한:**

1. 낙하물은 주차된 물체와 이미 떨어진 물체를 포함한 4개 중 3차원 거리상 가장 가까운 하나만 관측한다. 가까운 바닥 잔해 때문에 더 위험한 상공의 낙하물 정보가 빠질 수 있다.
2. 수평 광선은 root 높이와 겹치는 박스만 감지한다. 높이 샘플은 요철만 포함하므로, 천장 여유를 직접 나타내는 관측값이 없다.
3. 바닥은 위치와 속도만으로 완전히 관측되는 상태가 아니며, 진동 주파수·위상·다음 투하 시점은 제공되지 않는다. 기본 정책은 이력이 없는 feedforward ActorCritic이다. 필요한 정보의 일부는 시간 이력이 있어야 추정할 수 있다.
4. 실제 센서가 아닌 시뮬레이터 형상·상태의 직접 계산이다. 센서 잡음, 지연, 상공 시야·차폐는 모델링되지 않는다.
5. 평지와 비평지 입력 크기가 다르다. 기존 평지 가중치를 그대로 사용해 장애물 학습을 이어가는 경로는 없다. 같은 32개 추가 관측을 사용하는 환경끼리도 성능 전이가 검증된 것은 아니다.

**우선 비교할 보완:** 상방 여유 관측, 실제 낙하 중인 물체의 활성 마스크, 여러 위험 물체 또는 충돌 예상 시간 순으로 정렬한 정보, 2–4개 과거 관측의 이력. 관측을 바꾸면 체크포인트 입력 계약도 함께 관리해야 한다. 미래 투하 일정은 실제 시스템에서 얻을 수 있는 경우에만 정책 입력으로 사용하는 것이 맞다.

## 6. 보상과 종료 조건

근거: [보상 계수][env_cfg], [보상·종료·로그 구현][env]. 아래 합계는 할인 전이며 특별히 적지 않은 자세 변화·행동 비용은 제외했다.

| 항목 | 현재 계수 / 공식 | 크기 해석 |
| --- | --- | --- |
| 목표 접근 | `10 × clip(이전거리−현재거리, ±0.25)` | 목표에 10 cm 접근 시 +1 |
| 목표 방향 속도 | `0.50 × 속도 × dt` | 0.1 m/s로 20초 이동 시 +1 |
| 목표 방향 정렬 | `0.10 × heading × dt` | 정면을 향해 20초 유지 시 +2 |
| 수평 자세 | `0.25 × upright × dt` | 수평으로 20초 유지 시 +5 |
| 행동 변화 | `−0.015 × Σ(action−previous_action)² × dt` | 정규화 행동의 변화 비용. 실제 관절 가속도 비용은 아님 |
| 토크 | `−0.0003 × Σ(근사 토크²) × dt` | 24관절이 토크 상한을 20초 유지해도 약 −0.1385 |
| 수직 속도 | `−0.05 × 몸체 좌표계 수직속도² × dt` | 진동 바닥과 함께 움직여도 비용 발생 가능 |
| 목표 도착 | +20 | 거리 < 0.30 m |
| 낙상 | −3 | 높이 기준 미달 또는 기울기 기준 초과 |
| 낙하물 접촉 이벤트 | −2 | 링크별 필터 접촉력 중 하나가 2 N 초과하며 새 접촉 구간 시작 |

정면을 향해 수평으로 20초 정지하면 비용을 제외하고 **+7**이다. 반면 목표 방향으로 0.1 m/s씩 20초 이동하면 접근 +20, 속도 +1이 추가된다. 따라서 정지 보상이 있다는 이유만으로 **정지가 최적 정책이라고 단정할 수는 없다.** 다만 움직임이 자주 낙상으로 이어지는 초기에는 정지가 유리한 국소 행동이 될 수 있다.

비평지에서 목표 반경에 진입할 때까지 약 2.9 m 전진하면 접근 보상 약 +29와 도착 +20을 받는다. 이에 비해 피격 −2는 접근 약 0.2 m, 낙상 −3은 접근 약 0.3 m의 보상 크기다. 접촉을 줄이는 것이 주목적이라면 이 비율이 충분한지 피격률로 판단해야 한다. 토크 비용도 현재는 에너지 절감의 강한 제약이라고 보기 어렵다.

### 먼저 정리할 종료·집계 문제

- 목표 도달·낙상·영역 이탈은 종료되지만, 실패 벌점은 낙상에만 붙는다. 영역 이탈 전용 벌점과 종료 카운터는 없다. 종료 자체의 가치 학습 효과가 없다는 뜻은 아니다.
- 같은 스텝에 목표에 도착하면서 넘어지면 +20과 −3이 함께 적용되어 해당 두 항목의 합이 +17이고, 성공·낙상 로그에도 중복 집계된다. 성공과 실패의 우선순위를 정해야 한다.
- 기울기 종료 기준 `projected_gravity_z > −0.35`는 정상화된 중력 벡터에서 수직 방향 대비 약 **69.5° 초과**다. 비틀린 위험 자세를 어디까지 허용할지는 통과 과제의 기준과 맞춰야 한다.
- `Metrics/debris_impact`는 리셋 직전 제어 스텝의 플래그만 센다. 에피소드 중간의 피격을 누적한 횟수가 아니다. 보상 누계에는 비용이 남지만, 현재 지표만으로 피격률을 평가하면 누락된다.
- 접촉 이벤트는 모든 낙하물을 합친 boolean의 상승 구간을 사용한다. 동시 피격이나 다른 물체와 접촉이 이어지는 경우를 물체별 피격 횟수로 셀 수 없다.
- `Episode_Reward/*`는 실제 종료 시간과 관계없이 합계를 항상 20초로 나눈다. 실제 에피소드의 초당 평균 보상으로 해석하면 안 된다.

## 7. PPO 파라미터

근거: [PPO 설정][ppo_cfg], [상속 기본값][runner_cfg].

| 항목 | 현재 값 | 평가 |
| --- | --- | --- |
| actor / critic | 각각 [256, 128, 64], ELU | 현재 입력 크기에 구현상 모순은 없음. 네트워크 확대보다 관측·평가 개선이 우선 |
| 관측 정규화 | 활성 | 단위가 다른 속도·각도·거리를 다루는 데 유용. checkpoint와 통계 함께 사용 필요 |
| 초기 행동 표준편차 | 0.35 | 토크 포화 측정 후 0.20 / 0.30 / 0.35 비교 후보 |
| 초기 학습률 / 스케줄 | 3e−4 / adaptive | KL·손실 곡선 없이 상향·하향을 확정할 근거 없음 |
| PPO clip / 목표 KL | 0.2 / 0.008 | 우선 유지, 실제 KL과 업데이트 크기 기록 |
| entropy 계수 | 0.005 | 우선 유지, 탐색 크기·행동 클리핑 비율과 함께 확인 |
| epoch / minibatch 수 | 5 / 4 | 병렬 환경 수에 따라 minibatch 48↔384로 달라짐 |
| value loss 계수 / value clip | 1.0 / 활성 | 우선 유지 |
| 할인율 gamma | 0.995 | 50 Hz 기준 먼 미래 도착 보상의 가중치가 작음 |
| GAE lambda | 0.95 | 현재 dense progress와 함께 동작. 단독으로 좋고 나쁨을 판정하기 어려움 |
| gradient norm 제한 | 1.0 | 우선 유지 |
| 저장 주기 | 50 iteration | 32환경이면 76,800개의 새 transition마다 저장 |

시간 규모를 계산하면 다음과 같다.

```text
rollout 시간 = 48 × 0.02 = 0.96초
할인 가중치 유효합 시간 ≈ 0.02 / (1−0.995) = 4.00초
할인 가중치 반감기 ≈ 2.766초
gamma × lambda = 0.94525
GAE 가중치 유효합 시간 ≈ 0.02 / (1−0.94525) = 0.365초
```

도착 보상 +20의 현재 시점 가중치는 10초 뒤 도착이면 약 1.63, 20초 뒤라면 약 0.133이다. 그러나 critic bootstrap과 매 스텝의 접근 보상이 있으므로 이를 장기 보행을 학습할 수 없다는 뜻으로 해석하면 안 된다. PPO와 GAE는 수집된 경험 재사용, 가치 추정, 시간 가중치를 함께 고려해야 한다. [PPO 원 논문](https://arxiv.org/abs/1707.06347), [GAE 원 논문](https://arxiv.org/abs/1506.02438).

긴 대기나 우회 후 성공하는 행동이 학습되지 않을 때 `gamma=0.995 / 0.998 / 0.999`, rollout `48 / 96`을 비교할 수 있다. 먼저 위험 관측을 보완해야 시간 가중치 문제와 정보 부족을 분리할 수 있다.

| 항목 | 확인값 | 의미 |
| --- | --- | --- |
| 파일 크기 | 1,554,130 bytes | 현재 제공 파일 |
| 저장 iteration | 499 | 0부터 세는 마지막 인덱스라면 500회와 대응. 이것만으로 실행 이력 전체를 증명하지는 않음 |
| actor 첫 층 / 마지막 층 | [256, 84] / [24, 64] | 평지 84관측·24행동용 |
| critic 첫 층 | [256, 84] | 같은 입력 계약 |
| 정책 std 최소 / 평균 / 최대 | 0.77659 / 0.83189 / 0.91572 | 현재 새 학습의 초기 std 0.35와 구분해야 함 |

**평가:** 이 체크포인트는 새로운 116관측 환경에 직접 사용할 수 없다. 저장된 std가 크다는 사실만으로 보행 품질을 판정할 수도 없다. 결정론적 재생은 일반적으로 정책 평균을 사용하므로 학습 시 샘플링 표준편차와 구분해야 한다.

README에는 이전 500회 학습과 384,000 samples가 기록되어 있다. 현재 32환경 × 48 rollout × 500회는 768,000 transitions이므로, **기존 문서의 학습 기록을 현재 설정으로 다시 실행한 결과로 인용하면 안 된다.** 현재 로그가 없어 과거 rollout·환경 수·재개 이력은 확정할 수 없다. 기록된 낙상 0회·시간초과 32회도 새 장애물 환경의 성공률 근거가 아니다.

## 9. 권장 수정·비교 순서

| 2 | 행동 탐색 | 초기 std 0.20 / 0.30 / 0.35 비교. 필요 시 평활화 별도 비교 | 추종 오차, 포화 비율, 낙상률 |
| 2 | 시간과 안전 보상 | 관측을 보완한 뒤 gamma·피격 비용 등을 한 번에 한 항목씩 변경 | 피격 없이 완주하는 비율, 무기한 정지 여부 |
| 2 | 환경 난이도 | 진폭·주파수·낙하 질량·높이·빈도를 분리한 실험 | 실패 원인과 성능 저하 시작점 |
| 3 | 실물 대응 | 질량·관성·서보 지연·전원 조건·접촉 마찰을 측정한 뒤 보정 | 실측 추종/접촉 특성과 시뮬레이션 차이 |

환경 수를 비교할 때 iteration 수까지 똑같이 고정하면 경험 수가 달라져 결과를 혼동한다. 예를 들어 총 1,536,000 transitions를 맞추려면 rollout 48 기준으로 **4환경×8,000회 / 16환경×2,000회 / 32환경×1,000회**를 비교한다. 메모리 사용량과 처리량은 이번에 측정하지 않았으므로 32환경이 모든 GPU에서 가능하다고 단정하지 않는다.

마찰은 환경 재질의 정지 1.0 / 동적 0.9, multiply 조합으로 고정되어 있다. 실제 접촉 계수는 로봇 접촉 재질과 조합 규칙에도 좌우된다. 난이도 선택이나 시드만으로 마찰·서보 지연·질량 등이 랜덤화되는 것은 아니다.

## 10. 실행 환경 연결 후 평가 절차

1. Isaac Sim 경로를 연결하고 각 환경의 스모크 검사를 실행한다. 이는 물리 동작 검사이며 정책의 성공률 평가와 다르다.
2. 사용할 **로봇·관측 크기에 맞는 체크포인트 경로를 고정**한다. 비평지의 최신 모델 자동 검색은 같은 로봇의 다른 비평지 환경에서 학습한 모델도 선택할 수 있다.
3. 난이도 0 / 0.5 / 1, 시드 42 / 43 / 44로 비교한다. 16환경×10,000스텝은 환경별 명목 200초이며, 20초 에피소드 기준 약 160개 완료 구간을 얻을 수 있다. 실제 완료 에피소드 수와 부분 에피소드는 별도로 기록한다.
4. 성공률을 `성공 완료 에피소드 / 전체 완료 에피소드`로 계산하고 낙상·이탈·시간초과·피격을 함께 보고한다. 현재 성공·낙상 중복 집계를 먼저 정리해야 한다.

```powershell
# 경로는 설치 위치에 맞게 지정
.\setup_isaaclab.ps1 -IsaacSimPath "D:\path\to\isaac-sim-4.5"

# 진동과 실제 낙하, 부분 초기화까지 확인
.\run_isaaclab.ps1 -Mode smoke -Environment mixed -Difficulty 0.5 -NumEnvs 4 -Steps 200 -Seed 42

# 아래 경로는 실제 학습한 baseline 비평지 모델로 교체
.\run_isaaclab.ps1 -Mode evaluate -Environment falling_debris -Difficulty 0.5 -NumEnvs 16 -Steps 10000 -Seed 42 -Checkpoint "C:\path\to\obstacle_model.pt"
```

위 명령은 실행 계획이며 이번 평가에서 실행한 결과가 아니다. 현재 `evaluate.py`는 성공·낙상·시간초과 **횟수**, 평균 속도·거리·보상을 출력하지만 완료 에피소드별 완주시간, 누적 피격률, 이탈률을 모두 제공하지 않는다. `DKSH_ISAACLAB_EVAL_PASS`는 유한한 값으로 실행을 마쳤다는 표식이며 성공률 합격 기준이 아니다.

단위 테스트 재현 명령은 다음과 같다. CPU PyTorch가 없는 Python에서는 관련 테스트가 제외되므로, 이번에 사용한 작업 폴더의 가상환경을 명시했다.

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s .\isaaclab_project\tests -v
```
